> 本轮共 5 项用户反馈，全部落地并实机验证。基线：703 项测试全绿、
> clippy `--all-targets` 零警告、三个 GPU 探针（pipeline / blur /
> backdrop）退出码 0。

## 一、磨砂渲染：预测窗口移动轨迹，消除拖动时的轻微延迟

**现象**：拖动窗口时磨砂背景跟不上窗口，有一段「拖影」。

**根因（两条叠加）**

1. 底图是**捕获时**的桌面快照，而捕获按 [`CAPTURE_INTERVAL`] 节流
   到 30fps：窗口从 `P_cap` 移动到 `P_now` 后，底图内容相对窗口
   「过期」了 `d = P_now − P_cap`，看起来就是背景比窗口慢半拍；
2. 即使不节流，帧提交到真正呈现之间窗口还会再走一帧，仍然落后。

**做法**

| 层 | 改动 |
|---|---|
| `gfx/backdrop.rs` | 新增 `client_origin()`（每帧观测客户区原点）与 `MotionPredictor`（150ms 窗口内最小二乘拟合速度 + EMA 帧间隔 + 一帧外推，纯逻辑，9 项单测） |
| `gfx/shaders/blur.wgsl` | `fs_copy` 增加 push constant `copy_pc.offset`：合成时把采样坐标平移 `+d/尺寸` |
| `gfx/build.rs` | 校验能力加 `PUSH_CONSTANT`（naga 缺该能力会直接拒绝整个模块） |
| `gfx/pipeline.rs` | 新增 `PipelineLayout::with_push_constants`（旧 `new` 委托它传空） |
| `gfx/blur.rs` | `Blit` 带 `uv_offset`；`composite(offset)`；离屏 blit **每次推零**（`fs_copy` 声明了该常量，不推是未定义内容） |
| `gfx/frame.rs` | 底图绘制前推 `pre.uv_offset` |
| `ui/renderer.rs` | 每帧观测原点（**先于节流判断**，否则速度采样稀疏）；窗口移动时**强制重捕获**；捕获成功记录 `capture_origin`；`backdrop_uv_offset()` 算 `(预测位置 − 捕获位置)/交换链尺寸` |

**为什么除以交换链尺寸**：合成用的全屏三角形把 UV 映射到整个绘制目标，
无论目标是交换链还是超采样场景图，一像素物理位移都等于
`d / swap_extent` 个 UV 单位——两条路径口径一致。

**静止时位移恒为 0**，与加此机制前逐字节一致（无回归风险面）。

**验证**：`backdrop_probe` / `blur_probe` / `pipeline_probe` 退出码 0；
`backdrop::tests` 新增 9 项（静止速度 0、匀速拟合、一帧外推、停下后归零、
同刻去重、采样上限、`reset`、空 hwnd 拒绝）。

## 二、置顶模式切回「共用单栏」时宽度恢复默认

**现象**：切到「独立分栏」窗口被自动撑宽（并写回配置），切回
「共用单栏」窗口停在撑宽的宽度上，回不去。

**根因**：`resize_width_target` 只有「够宽就不动」一种语义
（当年为「别把用户手动拉宽的窗口改小」而设计），切回来时
`needed`（min_width 之和）远小于当前宽度 ⇒ 永远不动。

**做法**：`resize_width_target` 改为吃 `WidthRequest` 枚举：

- `AtLeast(points)`：原语义（切到独立分栏用，只放大）；
- `RestoreDefault`：精确恢复**默认宽度**（物理像素，取自
  `UiConfig::default().ui.window_width`，不写死数字）。

另修一处连带缺陷：`draw_segmented` 对**已选中项**也会上报 clicked，
不判「真的切换了」的话，在「共用单栏」状态下点一下已选项就会把
用户手动拉宽的窗口打回默认宽。

**验证**：`resize_tests` 7 项（新增 3 项：恢复默认、已是默认时不动、
恢复默认与 DPI 无关）。

## 三、MCP 设置：间距拥挤 + 状态文字渲染出界面

**现象 A**：MCP 总开关行的 ⓘ 与开关**贴在一起**。
**根因**：设置卡片把 `item_spacing.x` 归 0（行间距才够呼吸），
同行控件零间距就会挨上——热键行当年也踩过同一个坑（那里用
`add_space(8.0)` 修的）。
**做法**：同款 `ui.add_space(8.0)`。

**现象 B**：MCP 覆盖层的服务状态行**文字画到面板之外**。
**根因**：egui 的 `Label` 在**横向**布局（`ui.horizontal`）里默认
`TextWrapMode::Extend`——不换行也不截断，直接溢出容器。实测最长
状态（`Unconfigured`）单行拼接宽 **475.4pt**，而面板内缘只有
**448pt**（480 − 2×16）。
**做法**：拆两行——第一行「圆点 + MCP 服务：xx」，第二行单独放
`detail()`（纵向布局默认 `Wrap`）；徽标 44 → 50pt（三个 14pt 全角字
占 42pt，老宽度只剩 1pt 内边距）。

**验证**：
- 单测 `mcp_overlay_status_lines_fit_panel`：用真实字体度量，
  四态的状态行与说明都在内缘之内，且**锁死**「旧单行拼接放不下」
  （放得进说明回归锁失效）；
- 单测 `mcp_comm_card_registers_toggle_and_info` 加固为「间距 ≥ 7.5pt」；
- 实机（`scripts/verify_mcp_overlay.ps1` + `verify_ui_checks.py mcp`）：
  面板内状态文字 bbox 逻辑 `x[167,508]`（内缘右 614）✓，
  面板右缘外**亮像素 0** ✓。

## 四、主题切换失效

**现象**：在设置里切「深色 / 浅色 / 跟随系统」几乎没反应。

**根因**：主题补间的目标值恒为 `1.0`，而 `anim::tween_f32` 在目标
不变时是**惰性**的——首帧插入即 `from == to == 1.0`，之后永远返回
`1.0`，`draw_frame` 里 `if pal_mix < 1.0` 的分支再也不会执行
⇒ `self.pal` 从不更新。于是主窗口的 egui `Visuals` 变了（`set_theme`
立即灌入），而**自绘层与设置/子窗口全部停在旧主题**。

**做法**

1. `anim::restart(ctx, id, from, to, dur, ease)`：显式重播一段固定
   动画（3 项单测，含「惰性」与「重播」的对照）；
2. `Op::SetThemeMode` 里 `restart(pal_mix, 0 → 1)`，时长与帧循环共用
   常量 `theme::PALETTE_TWEEN`；
3. 顺带修一处「补间走完不落地」：`tween_f32` 到点后直接返回目标值，
   `mix < 1.0` 分支不再执行 ⇒ 显示值停在**最后一帧的近似值**上。
   现在补间结束时用 `pal != pal_to` 判断并精确落位（`Palette` 加
   `PartialEq`，逐字段比较只在补间结束后发生一次）。

**验证**：`app::tests::theme_switch_actually_changes_palette_and_restarts_tween`
（切完 `anim::busy` 为真、推进时间后精确等于目标色）；
实机（`verify_theme_font.ps1` + `verify_ui_checks.py theme`）：
窗口底色 `(20,22,26) → (242,244,247)` ✓。

## 五、字体缩放失效 + 预设档位

**现象**：设置里的「字体缩放」怎么改都没反应。

**根因**：`UiConfig::font_scale` **只有写入方、没有读取方**——全仓
grep 不到任何消费点（`theme.rs` 里只剩一句注释）。配置改了、落盘了，
界面一动不动。

**做法**

1. `Palette::with_font_scale(scale)`：由宏按**字段名前缀**（`font_*`）
   生成，只缩放字号令牌，几何/描边/动效令牌原样。判据用前缀而不是
   另维护名单——新增字号令牌忘记登记会静默不缩放；
2. `App` 新增 `pal_base`（1.0× 原色）与 `pal`（显示值）分离：缩放是
   **乘性**派生，在已缩放的调色板上再乘会叠乘（1.15² = 1.3225），
   所以每次都必须从 `pal_base` 重新派生；
3. 设置项由 `Number`（0.05 一档的 DragValue）换成 **`FontScale`
   分段预设**：小 85% / 标准 100% / 大 115% / 特大 130% / 超大 150%，
   右侧显示百分比读数（值不在预设上时标「自定义」，不假装选中最近档）；
4. 即改即生效（**不走补间**：字号变化会让每段文字重新排版，渐变观感
   是「抖」）；切主题时目标调色板带上当前缩放，不会把字号打回 1.0×；
5. `theme::clamp_font_scale` 统一钳制（0.75~2.0，NaN 回落 1.0——NaN
   会让所有字号变 NaN，egui 静默产出空 galley，表现为文字全部消失）。

**验证**：12 项测试（`with_font_scale` 只缩放字号 / 1.0× 恒等 /
非法输入回落 / 叠乘警示 / 预设表完整性 / 最近档 / 预设判定 /
点「大」推出 1.15 / 重置回 1.0 / 运行时生效且不叠乘 / 越界钳制 /
切主题保留缩放）；实机：导航文字宽 `43 → 64` 物理像素
（比值 **1.49**，期望 1.5）✓，日志 `字体缩放已应用 font_scale=1.5`。

## 六、本轮踩到的两个「取证」坑（写给下一轮）

1. **PowerShell 不声明 DPI 感知时，截图只覆盖屏幕左上角**。
   `Screen.Bounds` 返回虚拟化逻辑尺寸（本机 1707×1067），而
   `CopyFromScreen` 抓的是物理像素左上角那块——设置窗口（物理
   `858..2028`）会被截掉右半，于是「点击位置对、截图上量不到变化」，
   极易误判成「修复无效」。采集脚本必须先 `SetProcessDPIAware()`。
2. **配置种子文件不能带 BOM**。`Set-Content -Encoding UTF8` 会写
   BOM，`Config::load` 解析失败后**静默回落默认值**——日志里
   `configured=None` 是唯一线索。用
   `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`。
