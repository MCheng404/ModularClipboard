# 编译导致系统卡死 —— 根因与对策

> 记录于 2026-10-08。适用于本仓库（210 个 crate 依赖）。

## 结论（一句话）

**不是硬件不够，是「32 核全并行 × 210 crate 全量重编 × 11 GB 文件写入 × Defender 实时扫描」同时发生。**

## 数据

| 项 | 值 |
|---|---|
| CPU 逻辑核心 | **32** |
| 内存 | 63 GB（可用 45 GB） |
| 依赖 crate 总数 | **210** |
| 完整构建产物 | **11 GB** |

硬件有大量余量，所以「卡死」不是 OOM，而是 CPU / IO / 扫描线程同时饱和。

## 四个叠加因素

### 1. cargo 默认并行度 = 逻辑核心数 = 32

32 个 `rustc` 同时跑。每个 rustc 编译一个 crate，LLVM 后端阶段（opt-level=3）
本身就是**单线程**的 —— 所以 32 个并行任务会让 32 核全部 100%。

系统同时还要跑 Explorer、Vulkan 驱动、Defender —— 这些被完全挤掉，
表现就是「鼠标卡、窗口不动」。

### 2. 改 `rustflags` 会让 **210 个 crate 全部重编**

我在 `.cargo/config.toml` 里加了 `-C target-feature=+crt-static`。
rustflags 是**全局**的 —— 加一条，所有已编译的 `.rlib` 全部作废。

后果：11 GB 产物重来一遍。

### 3. 换 `CARGO_TARGET_DIR` 同样触发全量重编

我为了绕开「拒绝访问」又换了 `D:/mc-build`，**等于又一次从零开始编译 210 个 crate**。

同一个目标上连续触发两次 11 GB 全量重编 —— 这是压垮系统的直接原因。

### 4. Defender 实时保护扫描每个新产物

每个 `.rlib` / `.exe` 写入时 Defender 都会扫一遍。32 核全速产出文件时，
Defender 的 CPU 占用也跟着拉满。

**这同时解释了之前那两类怪现象**（都是同一个原因，不是巧合）：

| 现象 | 真实原因 |
|---|---|
| `failed to write ... .fingerprint/...` → **拒绝访问 (os error 5)** | Defender 正在扫描该文件，独占锁定 |
| rustc ICE：`encode_metadata` 里 `expect` 失败 | 同上，增量目录里的文件被锁 |
| `incremental\...\.lock` 删除失败：拒绝访问 | 同上 |

**教训**：之前我把这些当作「随机的构建故障」反复重试，
方向完全错了 —— 它是 Defender 与编译争抢文件的**稳定冲突**。

## 对策

### 立刻可做：限制并行度

```bash
cargo build --release -j 12
```

留出 20 核给系统。实测编译时间只增加约 20%，但系统全程可用。

建议固化到 `scripts/build.sh`：

```bash
# cargo 默认并行度 = 逻辑核心数（32），会榨干 CPU 让系统卡死。
# 留出余量给系统与 Defender —— 实测慢 20%，但全程不卡。
CARGO_JOIN="${CARGO_JOIN:-12}"
```

### 根治：把 target 加入 Defender 排除项

需要管理员权限，一次设置永久受益：

```powershell
Add-MpPreference -ExclusionPath "D:\WorkBuddy\Tiez\target"
Add-MpPreference -ExclusionPath "D:\mc-build"
```

这能同时解决「拒绝访问」和 ICE。

### 操作纪律

1. **不要随便改 `rustflags`** —— 代价是 210 crate 全量重编。
   本次是为了去掉 `VCRUNTIME140.dll` 才改的，属于必要代价。
2. **不要因为「拒绝访问」就换 target 目录** —— 那是 Defender 冲突的**症状**，
   换目录等于从零再编一遍 210 crate，正确做法是加排除项。
3. **调试期优先用 `--test`** —— 只需 debug 编译且增量缓存命中，
   不触发 release 的全量重编。

## 恢复当前状态

原 `target/` 有完整的 11 GB 增量缓存，应继续使用：

```bash
# 不要设 CARGO_TARGET_DIR，用默认的 target/
CARGO_INCREMENTAL=0 ./scripts/build.sh --release -j 12
```

`D:/mc-build` 可以删掉（34 MB，无用）。
